### Target State

The two JSON API endpoints (/api/payment-status, /api/risk-score) are
security-hardened in place: parameterized SQL, input validation, env-based
credentials, structured logging, HTTP security headers. The Held Payments screen
(/exceptions) is redesigned to Meridian Design Language 3.0 with full
WCAG 2.2 AA compliance. The modernized API is wrapped in an MCP server and
exposed to a watsonx Orchestrate agent under scoped-identity governance to
deflect the 340 weekly vendor hotline calls.

### Key Decisions

1. JSON APIs only in Phase 1 — XML feed (ERP batch bridge) deferred; no change window available
2. Modernize in place — Express + better-sqlite3 + EJS stack retained; 4 approved libraries added
3. Agent channel included — WS-4 (MCP + Orchestrate) in scope; write scope not granted to agent

- Automated suite (tests/equivalence.test.js) compares: status code, body fields, numerics, enums, booleans, error bodies
